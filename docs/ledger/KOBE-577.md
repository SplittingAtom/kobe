## Decisions

- **Keys include `team_id`** (house rule): `project_tree_entries` PK is (team_id, commit_id, path),
  `project_checkouts` PK (team_id, project_id, user_id), commits unique (team_id, project_id, seq
  DESC), which also serves the history page (no second index).
- **SQL-only foreign keys** (0200, like 0096): `projects_head_commit_fk` (drizzle cannot type two
  tables pointing at each other; NO ACTION, so the head can never be deleted, while a project
  delete still cascades), `project_commits_parent_fk` `ON DELETE SET NULL (parent_id)` (pruning
  keeps the oldest remaining commit), `project_commits_thread_fk` / `_run_fk` `SET NULL (col)`
  (history outlives a purged conversation). `project_checkouts_base_fk` is in drizzle (NO ACTION:
  pruning a checkout base is refused by the database too). Partial indexes back each SET NULL.
- **Same-project pointers (review):** `project_commits_project_commit_unique (team_id, project_id,
id)` is the target of the head key `(team_id, id, head_commit_id)`, the parent key `(team_id,
project_id, parent_id)` and the checkout base key `(team_id, project_id, base_commit_id)`, so none
  can name another project's commit. Migrations 0199/0200/0201 amended in place (unpushed).
- **Project delete under a hold:** the cascade into commit history raises KH001; `deleteProject`
  runs the delete in a savepoint and answers 409 `forbidden` ("legal hold"), like file removal.
- **Imported commit date:** `created_at` = newest `project_files.added_at` of the project
  (fallback `now()`).
- **Legal hold:** one function `project_history_legal_hold_guard` (project_files' rule: any active
  hold in the team) on DELETE of `project_commits` and `project_tree_entries`, plus the TRUNCATE
  refusal. Checkouts hold no content: no guard.
- **No break-glass read** on the new tables (spec silent; projects/project_members precedent).
  Project file content stays readable through `project_files`' existing policy. Easy to add later.
- **Object counters (GV2), smallest reading:** scratchspaces already count objects
  (`workspace_sync.blob_count`, `live_files`), so nothing new there. Projects get four columns on
  `projects` (not a separate table): `live_*` = head tree, `history_*` = distinct blobs only older
  commits reference (live + history = what the project holds). The server (KOBE-579) maintains
  them; the backfill sets live counters, history 0. `max_objects` null = site default.
- **Commit checks:** seq >= 1, parent ≠ self, author_kind user|agent, message 1..500 chars after
  trim (protocol trims and needs min 1), file_count 0..500, bytes >= 0. `tree` path/size/sha256
  checks are project_files' own.
- **Audit (GV4):** the seven new events defined in `audit/events.ts` and `docs/audit-log.md`;
  `project.created` carries `visibility`; `project.member_added` / `member_role_changed` use
  owner|editor|reader and `member_role_changed` carries `roles: {owner, editor, reader}` counts.
  Historical rows keep `membersMode`/`member`/`builder` (audit reads never re-parse payloads).
  Payload shapes for 578/579 (who writes them): `owner_transferred {toUserId, fromUserId|null}`,
  `checked_out {baseSeq|null}`, `checkout_discarded {userId, reason: discarded|member_removed}`,
  `committed {commitId, seq, authorKind, threadId?, runId?, added, modified, deleted, fileCount,
bytes}`, `commit_reverted {commitId, seq, revertedSeq}`, `history_pruned {commits, treeEntries,
blobsQueued, rule: commits|days|hard_cap}`.
- **Server switch (bridges removed):** deleted `authz/team-role.ts` and `projects/compat.ts`;
  `toProtocolTeamRole(x)` → `x` in routes/{approvals,runs,usage,thread-notebooks,thread-compact,
  thread-branch-summary,projects}.ts and projects/import.ts. `projects/{repository,access}.ts`
  and `routes/projects.ts` read/write `visibility` and owner|editor|reader directly; `reader` rows
  accepted (422 `role_not_supported_yet` gone); `toProject` fills `head_commit_id` and the four
  counters from the row. Raw SQL `members_mode = 'team'` → `visibility = 'workspace'` in
  projects/{access,mounts}.ts and policy/live-rule.ts (mount set unchanged in kind: MT1 is
  578's). `authz/permissions.ts` ranks `contributor`; mail role name; invite error text.
  Added (cheap, data at hand): `updateProject` audits `project.visibility_changed`;
  `setMemberRole` audits `roles`.
- **Web:** `TeamRole`/`TEAM_ROLES` say `contributor`, role label "Contributor" (WS5); the
  `builder` → `contributor` inline maps in the project pages removed. `lib/projects/api.ts`'s
  edge translation (visibility → membersMode, editor/reader → member for display) stays for 581.
- **Tests renamed `builder` → `contributor`** wherever it is a team role value (server db tests,
  web tests); user labels like `as.builder` / `builder@x.test` left alone.
- **db:rebase:** this branch has a generated migration (0199) and hand-written ones (0198, 0201),
  which `scripts/migration-plan.mjs` refuses to regenerate. If main moves before merge, rebase by
  hand (parallel-work.md "Hand-written migrations").

## Open for 578 / 579 / 580

- 578: `setMemberRole` / `addMember` accept reader; the matrix wiring (403 `read_only` for
  readers, restricted 404s everywhere) and MT1 mount-on-conversation are still yours; mounts today
  = explicit rows + every team member of a `workspace` project. Write `project.owner_transferred`
  and `project.checkout_discarded {reason: member_removed}` (PJ3).
- 579: maintain `projects.live_*`/`history_*` on every commit/prune; new blobs under
  `blobs/<sha256>`; pruning must delete tree entries/commits newest-safe (head and checkout bases
  are FK-protected; hold guard raises `KH001`); write `project.committed` etc. with the shapes
  above; `max_objects` null → chart default.
- 579: `removeProjectFile` / `deleteProjectObject` (projects/files.ts ~313/341, routes/projects.ts
  ~387) still delete the `files/<id>` object at once: that orphans the Imported commit's tree
  entry and leaks history blobs on project delete. Route removals (and project delete) through
  `retention_blob_deletions`, keyed on "no tree entry or head file still references the key".
- Release note: a project over 500 files (the limit is app-enforced) would fail
  `project_commits_counts` in the 0201 backfill and stop the upgrade.
- 581: the web edge (`lib/projects/api.ts`) still shows `reader` as "member"; a role edit there
  would send `editor` and so promote a reader.
- 580: nothing in the DB; `checkouts[]` comes from `project_checkouts`.
- Break-glass read on `project_commits` / `project_tree_entries` if the gate wants it.
